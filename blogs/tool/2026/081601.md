还记得昨天那篇 [RVC + Voicemeeter 实现变音输入输出](/blogs/tool/2026/081501.html) 吗？今天来个更简单的方案——`VB-CABLE`。

这可能是**最简单**的输入输出管理，但是无法支持更高的自定义和更高的稳定性。

## 📖 VB-CABLE 是什么

`VB-CABLE` 和 `Voicemeeter` 是同一家（VB-Audio）出品的**虚拟声卡**，但更纯粹：没有调音台、没有通道，就一根「虚拟线缆」。

安装后系统会多出一对设备：`CABLE Input`（虚拟扬声器）和 `CABLE Output`（虚拟麦克风），声音进 Input 就会原样从 Output 出来。

> 下载地址：<https://vb-audio.com/Cable/>

---

## 🛠️ 开始配置

### 第一步：RVC-GUI 设置

打开你的 RVC-GUI：

- **设备类型**：建议改成 `WASAPI`（比 MME 延迟低，不容易爆音）
- **输入设备**：`麦克风 (Realtek(R) Audio)`，直接硬件，不绕任何软件
- **输出设备**：找带 CABLE 字样的 Input，应该是 `CABLE-A Input (VB-Audio Cable A)` 或类似名称
- **底部单选按钮**：「输出变声」
- 最后点击「开始音频转换」

这里展开说说设备类型。RVC 下拉框里的这些选项，其实是 Windows 不同时代的音频 API：

| 设备类型      | 延迟            | 说明                                           |
| ------------- | --------------- | ---------------------------------------------- |
| `MME`         | 高（100ms+）    | Win 3.0 时代的上古 API，兼容性最好，所以是默认值 |
| `DirectSound` | 中              | DirectX 时代的游戏音频 API，现在存在感不高       |
| `WASAPI`      | 低（30ms 左右） | Vista 之后的现代 API，实时变声首选              |
| `ASIO`        | 极低（10ms 内） | 专业音频标准，绕过系统混音，需要声卡驱动支持    |

实时变声对延迟很敏感，MME 一百多毫秒的延迟说出去就自带「电台感」了，还容易爆音。所以没特殊需求直接选 `WASAPI` 就完事了。

### 第二步：Windows 声音设置

右键任务栏喇叭 → 声音设置：

- **输出（播放）**：默认设备选你的**真实耳机**（你听声音用）
- **输入（录制）**：默认设备选 `CABLE-A Output (VB-Audio Cable A)`（或带 CABLE 字样的 Output）

::: tip
信号流：RVC 把变声后的声音送进 `CABLE Input`，CABLE 自动转到 `CABLE Output`，微信等软件录到的就是变声后的声音。
:::

## ✅ 写在最后

整体思路一句话：物理麦克风 → RVC 变声 → CABLE Output → 系统默认输入，其他软件直接用。

如果想追求更高的稳定性和自定义化的话，可以使用 RVC VST + REAPER，这个我就不讲了（其实是我不会）。

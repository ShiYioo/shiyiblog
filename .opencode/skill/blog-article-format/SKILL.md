# 博客文章归纳与排版优化指南

本博客基于 **VuePress 2 + vuepress-theme-reco**，所有文章为 Markdown 文件，存放在 `blogs/` 目录下。本 Skill 定义了从「原始草稿」到「正式发布」的完整规范化流程。

---

## 一、文件命名与目录结构

### 1.1 目录层级

```
blogs/
├── {category}/          ← 分类目录（5 种）
│   └── {year}/          ← 年份目录（如 2025、2026）
│       └── {MMDDNN}.md  ← 文章文件
```

### 1.2 文件名规则

格式：**`MMDDNN.md`**（6 位数字，无年份前缀）

| 位段 | 含义             | 示例          |
| ---- | ---------------- | ------------- |
| `MM` | 月份（两位）     | `08` = 八月   |
| `DD` | 日期（两位）     | `03` = 三号   |
| `NN` | 当日序号（两位） | `01` = 第一篇 |

**示例：**

- `071101.md` → 7 月 11 日，第 1 篇
- `121702.md` → 12 月 17 日，第 2 篇
- `080301.md` → 8 月 3 日，第 1 篇

::: warning 常见错误
- ❌ `2026080301.md`（多了年份前缀，不符合 6 位规范）
- ❌ `august03.md`（非纯数字命名）
- ✅ `080301.md`（正确）
:::

### 1.3 如果文章放错了位置

当用户提供的草稿文件直接放在 `blogs/` 根目录（如 `blogs/2026080301.md`），需要：

1. 根据内容判断分类（见第二节）
2. 创建正确的目录路径 `blogs/{category}/{year}/`
3. 用规范文件名写入新文件
4. 删除原始的错误位置文件

## 二、分类判定指南

博客共有 **5 个分类**，根据文章核心主题选择最匹配的一个：

| 分类       | 目录名  | 适用场景                                                   | 典型标签                         |
| ---------- | ------- | ---------------------------------------------------------- | -------------------------------- |
| **日常随笔** | `daily` | 个人生活、工作日常、面试经历、心情记录、踩坑吐槽           | `work`, `share`, `onebot`        |
| **工具分享** | `tool`  | 工具推荐、服务分享、资源导航、软件/网站推荐                | `share`, `tools`, `ai`, `clash`  |
| **问题修复** | `fix`   | Bug 修复、问题排查、踩坑记录、部署/配置解决方案            | `debug`, `vpn`, `wireguard`, `ipsec` |
| **AI 相关**  | `ai`    | AI 工具使用、AI 开发经验、SpringAI、自动化                 | `ai`, `springai`, `springboot`   |
| **面试八股** | `bagu`  | 技术原理总结、面试题解析、源码分析、知识体系梳理           | `java`, `kotlin`, `vue`, `nginx` |

### 判定优先级

当一篇文章跨多个主题时，按以下优先级选择**唯一主分类**：

1. **核心叙事是什么？** — 文章的主线和标题指向的主题
2. **读者期望什么？** — 读者点进来想获取什么价值
3. **次要内容用标签补充** — 不作为主分类

**典型例子：**
- 「在公司很闲，顺手更新了开源项目」→ 日常叙事为主线 → `daily`（标签加 `share` 补充）
- 「分享几个好用的 AI 中转站」→ 核心就是推荐工具 → `tool`
- 「ES 同步慢 + Token 白名单大坑」→ 核心是排查问题 → `fix`

## 三、Frontmatter 规范

每篇文章**必须**以 YAML frontmatter 开头：

```yaml
---
title: 文章标题
date: YYYY/M/D
tags:
  - tag1
  - tag2
categories:
  - category_name
---
```

### 字段说明

| 字段         | 必填 | 格式                          | 说明                                              |
| ------------ | ---- | ----------------------------- | ------------------------------------------------- |
| `title`      | 是   | 纯文本                        | 文章标题，不加书名号                              |
| `date`       | 是   | `YYYY/M/D` 或 `YYYY/MM/DD`    | 发布日期，两种格式均可但同一篇内保持一致          |
| `tags`       | 是   | 列表（每项前加 `  - `）       | 1-3 个标签，优先复用已有标签                      |
| `categories` | 是   | 列表（与目录名一致）          | 只有一个，且必须与所在目录名完全匹配              |

### 已有标签库（优先复用）

```
ai, c, clash, debug, gcc, gradle, idea, ipsec,
java, javafx, javascript, kotlin, linux, nginx,
onebot, rtmp, share, springai, springboot, tools,
vm, vpn, vue, windows, wireguard, work
```

::: tip
如果没有合适的已有标签，可以创建新标签，但应使用小写英文，语义清晰，避免与已有标签重叠。
:::

## 四、内容结构模板

### 4.1 通用骨架

```markdown
---
(frontmatter)
---

（1-2 句开场白，直接切入主题）

## {emoji} {章节标题}

（正文内容）

---

## {emoji} {章节标题}

（正文内容）

---

## {emoji} 总结

（收尾总结）
```

#### daily（日常随笔）

```
开场白（1-2 句交代背景）

## 🫠 / 📌 / 🤔 {主题标题}
（叙事正文，短段落为主）

---

## 🎉 / 💡 {结果/感悟}
（收尾，可以用 ::: tip 总结）

::: tip
总结感悟
:::
```

#### fix（问题修复）

```
## 背景
（问题描述，发生了什么）

---

## 🔍 / 🤔 {排查分析标题}
（排查过程，按步骤展开）

---

## 🛠️ {解决方案标题}
（具体修复方案，附代码/命令）

---

## ✅ / 📝 总结
（经验教训）

::: tip / ::: danger
核心教训

```

```

（收尾，预告后续）
```

```

|------|---|---|
（对比表格）

补充建议

```

```

（使用场景）

---
```

## 五、排版增强规范（提升阅读兴趣）

### 5.1 Emoji 章节标题

每个二级标题**推荐**加一个 emoji 前缀，增加视觉辨识度和个人风格：

| 用途           | 推荐 emoji                                   |
| -------------- | -------------------------------------------- |
| 背景/介绍      | `📌` `📖`                                    |
| 思考/分析      | `🤔` `🔍` `🧐`                               |
| 对比/选择      | `🆚` `🎯`                                    |
| 实施/操作      | `🛠️` `⚙️`                                    |
| 方案/灵感      | `💡` `✨`                                    |
| 总结/收尾      | `✅` `📝` `🎉`                               |
| 防护/警告      | `🛡️` `⚠️`                                    |
| 情绪/吐槽      | `🫠` `🤬` `📉` `📦`                          |
| 信息/说明      | `ℹ️` `📦`                                    |

::: tip
不是所有标题都必须加 emoji。「背景」「总结」等常规标题可以不加，但内容性标题（分析、对比、实施）推荐加。同一篇文章内风格保持一致。
:::

### 5.2 容器块（VuePress Containers）

用于强调不同重要程度的内容，是本博客的核心排版特色：

```
::: tip
提示性内容（绿色边框）—— 友好建议、小技巧、补充说明
:::

::: info
信息性内容（蓝色边框）—— 背景知识、概念解释、参考资料
:::

::: warning
警告性内容（黄色边框）—— 注意事项、潜在风险、不推荐的做法
:::

::: danger
危险/严重内容（红色边框）—— 严重后果、数据丢失风险、强烈警告
:::
```

**使用原则：**
- 一篇文章中容器块不宜超过 5 个，过多会失去强调效果
- 容器内容要简洁，1-4 行为佳，大段内容应放正文
- `::: tip` 最常用，`::: danger` 用于真正严重的警告

### 5.3 文本格式化

| 格式         | 语法             | 使用场景                                         |
| ------------ | ---------------- | ------------------------------------------------ |
| **加粗**     | `**文本**`       | 关键词、重点强调、数字指标（如 **5 分钟**）       |
| `行内代码`   | `` `文本` ``     | 技术名词、命令、文件名、字段名、配置值            |
| ~~删除线~~   | `~~文本~~`       | 吐槽、反讽、被否定的内容                          |
| > 引用块     | `> 文本`         | 外部链接地址、参考文献、引用名言                  |

### 5.4 分隔线

用 `---` 分隔**主要章节**，增加页面呼吸感：

```markdown
## 第一章节

内容...

---

## 第二章节

内容...
```

::: warning
不要每个小标题之间都加分隔线，只在**一级章节**（二级标题 `##`）之间使用。三级标题（`###`）之间不需要。
:::

### 5.5 列表

**无序列表** — 用于枚举、特征列举：

```markdown
- 支持多设备
- 速度还不错
- 有免费额度
```

**有序列表** — 用于步骤、排名：

```markdown
1. 上传镜像到 PVE
2. 创建虚拟机
3. 导入磁盘
```

**带说明的列表** — 常用于配置项说明：

```markdown
- **名称**：openwrt，虚拟机名称
- **VM ID**：100，默认即可
- **内存**：512 MiB，作为主路由足够
```

### 5.6 表格

用于**结构化对比**，比纯文字列表更清晰：

```markdown
| 配置项 | 值 | 说明 |
|--------|-----|------|
| 核心数 | 2 个 | 取决于 CPU 性能 |
| 内存 | 512 MiB | 主路由足够 |
```

**适用场景：**
- 技术方案对比
- 配置项说明
- 功能特性对比
- 步骤参数说明

### 5.7 代码块

必须标注语言类型：

````markdown
```bash
sudo timedatectl set-timezone Asia/Shanghai
```

```java
LocalTime now = LocalTime.now(ZoneId.of("Asia/Shanghai"));
```
````

### 5.8 链接格式

**外部链接** — 使用引用块格式：

```markdown
> 地址：<https://example.com>
```

**参考文献** — 文末列出：

```markdown
> 参考文献：
>
> - [https://example.com/article1](https://example.com/article1)
> - [https://example.com/article2](https://example.com/article2)
```

## 六、写作风格指南

### 6.1 语气

- **口语化、接地气**：用「我」「大家」等人称，像和朋友聊天
- **有情绪、有态度**：可以吐槽（`666`、`我服了`）、可以感叹（`我靠`）
- **真诚分享**：记录真实的踩坑经历，不回避错误

### 6.2 段落

- **短段落优先**：每段 1-3 句话，避免大段文字墙
- **一句话也能成段**：在情绪转折或重点强调时使用
- **适当留白**：段落之间空一行

### 6.3 结构节奏

好的文章结构像讲故事：

```
背景（发生了什么）→ 冲突/问题（遇到了什么困难）→ 探索（怎么排查/思考）
→ 解决（怎么做的）→ 总结（学到了什么）
```

### 6.4 增强可读性的技巧

1. **数字具体化**：不写「很慢」，写「**45 秒**」
2. **对比制造冲突**：「正常人会觉得 coverUrl 是封面图吧？**错误的**」
3. **用容器块制造层次**：正文叙事 → `::: tip` 补充 → `::: warning` 警告
4. **适当用 emoji 表达情绪**：`😂` `🤡` `😮‍💨`（但不滥用）
5. **代码和命令用行内代码**：`apt install` 而不是 apt install

## 七、完整优化流程清单

当收到一篇草稿文章时，按以下步骤处理：

### Step 1：判断分类
- [ ] 通读全文，确定核心主题
- [ ] 匹配到 5 个分类之一（`daily` / `tool` / `fix` / `ai` / `bagu`）
- [ ] 如果跨主题，按「核心叙事」选择主分类，次要内容用标签补充

### Step 2：确定文件位置和命名
- [ ] 根据分类确定目录：`blogs/{category}/{year}/`
- [ ] 根据日期确定文件名：`{MM}{DD}{NN}.md`
- [ ] 如果原文件位置/命名错误，创建正确的新文件并删除旧文件

### Step 3：生成 Frontmatter
- [ ] `title`：提炼一个吸引人的标题
- [ ] `date`：按 `YYYY/M/D` 格式填写
- [ ] `tags`：选 1-3 个标签，优先复用已有标签
- [ ] `categories`：与目录名一致

### Step 4：结构化内容
- [ ] 将流水账文字重组为「背景 → 分析 → 解决 → 总结」结构
- [ ] 添加 emoji 二级标题（`## {emoji} 标题`）
- [ ] 在主要章节之间添加 `---` 分隔线
- [ ] 将碎散信息归入合适的容器块（`::: tip` / `::: warning` / `::: info` / `::: danger`）

### Step 5：排版增强
- [ ] 关键词、数字加 **加粗**
- [ ] 技术名词用 `行内代码`
- [ ] 结构化数据转为表格
- [ ] 命令/代码用代码块（标注语言）
- [ ] 链接用引用块格式
- [ ] 碎短段落合并，大段落拆分

### Step 6：语气润色
- [ ] 保持口语化风格，不要过于书面
- [ ] 适当添加情绪表达和 emoji
- [ ] 确保「短段落 + 留白」的节奏感
- [ ] 检查是否有「文字墙」，拆分为更短的段落

### Step 7：验证
- [ ] frontmatter 格式正确，`categories` 与目录名匹配
- [ ] 文件路径和命名符合 `blogs/{category}/{year}/{MMDDNN}.md` 规范
- [ ] 容器块语法正确（`:::` 开头和结尾）
- [ ] 无残留的 HTML 标签或不规范的 markdown

## 八、优化前后对比示例

### 优化前（草稿）

```markdown
关于最近闲到什么程度


在公司的时候大部分时候很闲，只有有时候突然会非常忙

闲到什么程度呢

刚开始的时候是水群

然后是刷抖音

再后面是玩小游戏

然后就开始直接追番了

其实这还不叫闲

如何叫闲呢

我在公司的时候把之前的开源项目更新了一下
...
```

### 优化后

```markdown
---
title: 关于最近闲到什么程度
date: 2026/8/3
tags:
  - work
  - share
categories:
  - daily
---

在公司的时候大部分时候很闲，只有有时候突然会非常忙。

## 🫠 闲到什么程度呢

刚开始的时候是**水群**，然后是**刷抖音**，再后面是**玩小游戏**，
然后就开始直接**追番**了。

其实这还不叫闲。

如何叫闲呢？我在公司的时候把之前的**开源项目**更新了一下...

::: tip
主要是做的是 `chmlfrp` 的客户端，之前用的比较多，就做了两个小玩意。
:::

---

## 📦 chmlfrp 是什么

`chmlfrp` 是一个**内网穿透服务商**...
```

**优化要点总结：**
1. 补全 frontmatter（分类 `daily`，标签 `work` + `share`）
2. 碎散单行段落合并为完整段落
3. 关键词加粗（水群、刷抖音、追番）
4. 技术名词用行内代码（`chmlfrp`）
5. 补充内容用 `::: tip` 容器块
6. 添加 emoji 章节标题和分隔线
7. 保持口语化语气不变
